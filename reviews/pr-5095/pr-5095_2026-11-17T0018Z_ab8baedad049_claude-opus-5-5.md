## Beyond the rules

- Stored bid responses are dropped. For a stored bid response Prebid Server removes the imp from the bidder's request (git 4e296450de2f:exchange/utils.go:216-218) and calls MakeBids with the text "Stored bid response for impression id: <id>" as the request body, an empty URI and no ImpIDs (git ab8baedad049:exchange/bidder.go:801-808, reached from :256-266 and :306). MakeBids decodes that body as a bid request (git ab8baedad049:adapters/sellwild/sellwild.go:152-154), which fails, so it returns that error and no bids; and since the imp is in neither the body nor the request, the impid check (:185-190) would refuse the bid as well. So every stored bid response for sellwild is lost; an independent run of core's requestBid path with a stored response gave sellwild 0 bids and the decode error, and core's own test bidder 1 bid. No JSON test can reach the path, as the framework always passes MakeBids the fixture's request (git ab8baedad049:adapters/adapterstest/test_json.go:500); :152-154 is uncovered (record go-checks sellwild-ab8baedad049 v1 coverage.uncovered[2]). Panxo, the adapter merged at base, detects a stored response by its empty URI and missing ImpIDs (git 4e296450de2f:adapters/panxo/panxo.go:307-311). The nine adapters at base that decode the outbound body in MakeBids lose stored bid responses the same way, and the PR 5099 review found the same for growzee. The auction docs present stored bid responses as a testing and debugging tool.
- The token reaches debug output through resolvedrequest. debug.allow false (sellwild.yaml:17-19) leaves this bidder's calls out of ext.debug.httpcalls, unless the host's debug-override header is set (git ab8baedad049:exchange/bidder.go:287-298). But with test 1 or ext.prebid.debug, and account debug allowed (the default, git ab8baedad049:config/config.go:1237; git ab8baedad049:exchange/utils.go:999-1007), Prebid Server returns the incoming request, stored requests merged, as ext.debug.resolvedrequest (git ab8baedad049:exchange/exchange.go:283-294, :1241-1245), and that request still holds imp.ext.prebid.bidder.sellwild.token. The docs PR advises keeping the token in server-side stored requests or stored impressions (prebid/prebid.github.io#6951, dev-docs/bidders/sellwild.md:32), so a caller who sends such a stored request with test 1 gets the token back. Traced in the code, not run.
- The tests build the adapter with the production endpoint, https://exchange.sellwild.com/exchange/openrtb2/{{.PublisherID}} (git ab8baedad049:adapters/sellwild/sellwild_test.go:14), and every fixture's expected uri uses that host; the published guide says to use an obviously fake endpoint for tests (https://docs.prebid.org/prebid-server/developers/add-new-bidder-go.html#adapter-code-tests). The path rule still holds with a fake host that keeps the path.

The guide says an endpoint that supports floors in one currency only must have them converted (https://docs.prebid.org/prebid-server/developers/add-new-bidder-go.html#makerequests); whether the exchange accepts any bidfloorcur is not known here.

In production requestData.ImpIDs carries the same ids (set at :94), but the JSON test framework passes MakeBids only the method, URI and body (git ab8baedad049:adapters/adapterstest/test_json.go:194-199), so a JSON test could not exercise an ImpIDs check.
