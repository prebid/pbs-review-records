## Beyond the rules

- Stored bid responses are dropped. For a stored bid response Prebid Server removes the imp from the bidder's request (git 4e296450de2f:exchange/utils.go:216-218) and calls MakeBids with the text "Stored bid response for impression id: <id>" as the request body, an empty URI and no ImpIDs (git dbf39b7b9a39:exchange/bidder.go:801-808, called at :306). MakeBids decodes that body as a bid request (git dbf39b7b9a39:adapters/bid9/bid9.go:164-167), which fails, so it returns a BadInput error and no bids; and since the imp is in neither the body nor the request, the impid check (:179-185) would refuse the bid as well. Core also rewrites stored-response impids only after MakeBids (git dbf39b7b9a39:exchange/bidder.go:363-375), so looking the imp up in the request alone would not fix it. Two independent readers reproduced the drop through core's own path. TestMakeBidsInvalidRequestBody (bid9_test.go:67-76) expects an error and no response for a body that is not JSON. The nine adapters at base that decode the sent body in MakeBids (floxis, merged 2026-10-22, the latest) drop stored bid responses the same way; panxo, merged at base, detects a stored response by its empty URI and missing ImpIDs (git 4e296450de2f:adapters/panxo/panxo.go:307-311). The PR 5099 and PR 5095 reviews found the same for growzee and sellwild.
- publisherId rarely takes effect on Prebid Server. The adapter sets site.publisher.id or app.publisher.id only when it is empty (bid9.go:92-94, :136-146), but Prebid.js's Prebid Server adapter fills an empty publisher id with the host's accountId (prebid/Prebid.js modules/prebidServerBidAdapter/ortbConverter.js:68-72), and the AMP endpoint fills it from the account (git dbf39b7b9a39:endpoints/openrtb2/amp_auction.go:837). So bid9 gets the host's account id there, and the param reaches the endpoint only in imp.ext.bid9.publisherId. The description says "when empty"; the docs page says the param is "sent as site.publisher.id / app.publisher.id" (prebid.github.io dev-docs/bidders/bid9.md:40). Client-side, the field is usually empty, so the Prebid.js adapter's same rule does set it.
- Removing an unresolved macro can break the next query parameter. removeUnresolvedMacros (bid9.go:231-250, pattern at :28) removes a parameter whose value is a macro with no value, with the separator after it. When that parameter is the first of an &amp;-escaped URL in adm (HTML attributes and VAST outside CDATA escape & this way), `?s=${AUCTION_SEAT_ID}&amp;b=2` becomes `?amp;b=2`, and b is lost; read from the pattern. supplemental/macros-without-value.json covers the middle position, which works. A macro used as a path segment leaves an empty segment.
- The iframe sync is Aniview's page, and it is heavy. The URL is player.aniview.com/ssync/ssync.html with pid 6960dc1469411be87d0ad78e and the [AV_UID] macro (bid9.yaml:22). Run in Chromium by the local server, it set the bid9 cookie entry, and in its first 15 s it started 591 requests to 152 hosts, about 270 KB, and had not gone quiet (record local-server bid9-dbf39b7b9a39 v5 browserSyncs[0].pageCost, msToQuiet 15173 over capMs 15000). The hosts include many other companies' sync endpoints, so the page syncs far beyond bid9. Measured once, from one machine.
- Aniview: the open Aniview adapter, github https://github.com/prebid/prebid-server/pull/4852 (two approvals; a commenter asked for the next release on 2026-11-04, and an approver asked for it to be added to the release on 2026-11-10), declares https://rtb.aniview.com/sspRTB2 and the same player.aniview.com sync page with [AV_UID]. bid9 declares https://rtb.bid9.ad/sspRTB2. The two adapters' Go code differs (similarity compares only with adapters at the target, and #4852's aniview.go is structured differently), so this is a platform match, not a code copy. The description calls the Aniview page "bid9's sync page". Whether the pid is bid9-wide, not one host's or publisher's, is not known here.
- The nurl to burl move. moveWinNoticeToBillingURL (bid9.go:252-262) moves nurl to burl and clears nurl when a bid has markup and no burl; no adapter at base does this. The guide says nothing about nurl or burl, and says adapters must not modify bids from demand partners except gross-to-net or currency (#respect-the-rules). The description's reason is that nurl is not fired on the server-side path; for a banner bid Prebid.js does fire nurl, as a pixel before adm (prebid/Prebid.js libraries/ortbConverter/processors/banner.js:36-37), and for video it would take nurl as the VAST URL, so the move is roughly neutral for banner and avoids a wrong VAST URL for video. Left to the maintainer; not raised.
- Macro resolution: the adapter fills ${AUCTION_PRICE} and six other ${AUCTION_*} macros in adm, nurl and burl, which the guide recommends ("We recommend resolving creative OpenRTB macros in your adapter"), and drops a macro with no value. Values are query-escaped everywhere, also inside markup text (bid9.go:222); request ids are normally UUIDs, so this rarely shows. Not raised.
- Floor params: bidFloor and bidFloorCur set imp.bidfloor and imp.bidfloorcur when the imp has none (bid9.go:84-90). The guide asks that params not include floors (#bidder-parameters), but it also requires parameters consistent between a bidder's client- and server-side adapters (#respect-the-rules), and the merged Prebid.js bid9 adapter has both params; 24 of 282 params schemas at base have a bidFloor param. Floors go to the endpoint in whatever currency they carry; whether the endpoint takes one currency only is not known. Not raised.
- Bid type: getMediaType (bid9.go:264-282) maps mtype 1 and 2; any other value, or none, falls back to the imp's formats and then to a VAST regex on adm (:23, :278), so an mtype 4 bid is typed by the imp (supplemental/unsupported-mtype-inferred.json), and a multi-format bid whose markup starts with <?xml is typed video. Prebid Server's semgrep adapter rules report nothing on bid9.go, here and in CI. Not shown in real data; not raised.
- Why `no-needless-json-roundtrips` holds: MakeBids decodes its own outbound body (bid9.go:165) to match each bid to the request's one imp. In production requestData.ImpIDs carries the same id (set at :111), but the JSON test framework passes MakeBids only the method, URI and body (git dbf39b7b9a39:adapters/adapterstest/test_json.go:194-199), so a JSON test could not exercise an ImpIDs check; nine adapters at base decode the outbound body in MakeBids. The review of this PR on 2026-11-15 (never published or posted) judged it does-not-hold, as did the PR 5099 review; the PR 5095 review weighed the test framework and judged it holds, as this one does.
- Endpoint timing: the endpoint answered an OpenRTB body without tagid with 400 only after 5.3, 6.4 and 5.3 s (record endpoint-check bid9-dbf39b7b9a39 v6 probes[0].observations.pbs.secondsPerRound); the local server's call with tagid=chan-a got its 404 inside a 262 ms auction (record local-server bid9-dbf39b7b9a39 v5 auction.durationMs), so the delay may depend on the missing tagid. One machine; not raised.
- The maintainer field lists two addresses in one string; Prebid Server reads maintainer.email as one value (shown as given at /info/bidders/bid9: record local-server bid9-dbf39b7b9a39 v5 info). No bidder-info file at base lists more than one.
- The docs PR (prebid/prebid.github.io#6856) merged on 2026-11-11 with pbs true while this PR is open.
