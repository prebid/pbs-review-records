## Beyond the rules

- przemkaczmarek asked whether ScrubDeviceIDsIPsUserDemoExt's fieldName parameter is still needed (every caller passes "eids"); the author kept it for a field other than eids, with a test, and przemkaczmarek approved. Not raised again.
- What the PR changes. ScrubGdprID and ScrubDeviceIDsIPsUserDemoExt with "eids" now call ScrubEIDs, which clears the OpenRTB 2.6 user.eids and the 2.5 user.ext.eids (git c7c28fd3bfa8:privacy/scrubber.go:69-75, :118-128, :144-148). Their callers in applyPrivacy are GDPR without PassID (git c7c28fd3bfa8:exchange/utils.go:381-382), US Privacy enforced (:386-387, :402-403), and enforced LMT or COPPA (:407-408). Before, only user.ext.eids was removed (git 4e296450de2f:privacy/scrubber.go, ScrubGdprID and ScrubDeviceIDsIPsUserDemoExt), and a request is upconverted to 2.6 first, so EIDs reached bidders under these signals (https://github.com/prebid/prebid-server/issues/5076). ScrubDeviceIDsIPsUserDemoExt keeps its fieldName parameter for a field other than eids (git c7c28fd3bfa8:privacy/scrubber.go:122-128), as the author answered przemkaczmarek.
- Bidders do not share what is scrubbed: applyPrivacy clones the request before any scrubber runs (git c7c28fd3bfa8:exchange/utils.go:371-372), CloneBidRequestPartial (git c7c28fd3bfa8:ortb/clone.go:265-279) deep-copies User with CloneUser, its EIDs included (:57-73, :69), and each bidder's parsed user.ext is its own (CloneAndClearImpWrappers, git c7c28fd3bfa8:exchange/utils.go:157; git c7c28fd3bfa8:openrtb_ext/request_wrapper.go:434), so clearing one bidder's EIDs leaves another's and the original request's. Order in cleanOpenRTBRequests: applyFPD (git c7c28fd3bfa8:exchange/utils.go:202) runs before applyPrivacy (:205) and the 2.5 downgrade after it (:225), which moves nothing back when user.eids is nil (git c7c28fd3bfa8:openrtb_ext/convert_down.go:136).
- Tests: TestCleanOpenRTBRequestsPrivacyEIDs (git c7c28fd3bfa8:exchange/utils_test.go) runs 8 policies (permitted, GDPR restricted and permitted, COPPA, LMT and US Privacy enforced and not) over 2.5 and 2.6 input and output, 32 cases, with the GDPR permission mocked. TestIdentityScrubbersRemoveEIDs (git c7c28fd3bfa8:privacy/scrubber_test.go) runs ScrubGdprID and ScrubDeviceIDsIPsUserDemoExt with EIDs in 2.5, 2.6, both, none and no user; TestScrubDeviceIDsIPsUserDemoExtOtherField checks that EIDs stay when another ext field is scrubbed. The PR changes TestCleanOpenRTBRequestsWithOpenRTBDowngrade (git c7c28fd3bfa8:exchange/utils_test.go:2565-2590) to expect no EIDs; its permissions mock leaves PassID false and it already expected the user's IDs removed, so that agrees. The corrected fixture exchange/exchangetest/multi-bids-different-ortb-versions.json is a GDPR, COPPA and US Privacy opt-out request (regs.gdpr 1, coppa 1, us_privacy 1YYY), so expecting no EIDs agrees with its other scrubbing.
- Prebid Server Java already removes EIDs under COPPA and US Privacy: UserFpdCoppaMask and UserFpdCcpaMask call maskUser(user, true, true) (https://github.com/prebid/prebid-server-java, src/main/java/org/prebid/server/auction/privacy/enforcement/mask/, read at its master 9ac33456c4d5). Under TCF it removes them when user IDs must be removed or LMT applies, except for sources in its TCF purpose 4 EID exceptions setting (TcfEnforcement, maskUserIds with getEidExceptions). PBS-Go has no EID exceptions (no eid_exceptions setting at 4e296450de2f), so with this PR GDPR without PassID removes every EID. A parity point for the maintainers; not raised.
- The published privacy page (prebid-server/features/pbs-privacy.md in prebid/prebid.github.io) lists what Limit Ad Tracking, COPPA and US Privacy remove, and none of its lists has user.eids; its GDPR section's "Passing User IDs" row names extended IDs only for a PBS-Java purpose 4 setting. With this PR PBS-Go removes EIDs in all four cases. Raised.
- For existing traffic this is a behavior change: bidders stop getting EIDs under these signals in PBS-Go, as the issue asks and Java does. Two cases reach more traffic than the signals' names suggest. Prebid Server sets device.lmt to 1 itself for an iOS 14.2+ app request whose ATT status is not determined, restricted or denied (git c7c28fd3bfa8:privacy/lmt/ios.go:57-63, from git c7c28fd3bfa8:endpoints/openrtb2/auction.go:570), and lmt.enforce defaults to true (git c7c28fd3bfa8:config/config.go:1226; read at git c7c28fd3bfa8:exchange/utils.go:123), so such requests now reach bidders without EIDs; a host can keep them only by turning off lmt.enforce, which also stops IFA scrubbing. And GDPR permissions fall back to PassID false when consent is missing or does not parse, or the vendor lookup fails (git c7c28fd3bfa8:gdpr/impl.go:71-84). Raised for the release note.
- ScrubUserFPD, which the PR leaves as it is, sets reqWrapper.User.EIDs = nil without checking User (git c7c28fd3bfa8:privacy/scrubber.go:137-142); ScrubEIDs checks it (:71). Its callers are applyPrivacy when transmitUfpd is denied (git c7c28fd3bfa8:exchange/utils.go:377-378), the analytics build (git c7c28fd3bfa8:analytics/build/build.go:157-158) and the hook executor (git c7c28fd3bfa8:hooks/hookexecution/execution.go:352-353), none of which checks User first, so a request with no user object, for a bidder with no cookie uid or FPD user, reaches it when transmitUfpd is denied. Since the scrubber refactoring of 2023 (https://github.com/prebid/prebid-server/pull/3108). It also clears only the 2.6 user.eids. The open https://github.com/prebid/prebid-server/pull/4953 (2026-08-30, no reviews yet) adds the nil check and a test. Not raised: it is not in this PR's diff and has its own PR.

## For the author

- **Privacy docs page**: The Prebid Server privacy page (`prebid-server/features/pbs-privacy.md` in prebid/prebid.github.io) lists what Limit Ad Tracking, COPPA and US Privacy remove, and none of the lists has `user.eids`; with this PR PBS-Go removes EIDs in each case, as PBS-Java already does for COPPA and US Privacy. A docs PR adding EIDs to those lists, linked from this PR, would keep the page in step.

So with this PR such requests reach bidders without EIDs, and a host can keep them only by turning off `lmt.enforce`, which also stops IFA scrubbing; worth stating in the description for the release notes.
