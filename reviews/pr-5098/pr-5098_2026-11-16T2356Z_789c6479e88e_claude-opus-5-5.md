## Beyond the rules

- What the change does: in MakeBids, a video bid whose adm starts with `http://` or `https://` gets that adm replaced by a VAST 3.0 wrapper whose VASTAdTagURI is the URL, escaped as XML text (git 789c6479e88e:adapters/cwire/cwire.go:100-107). Other video bids and every banner bid are left as they are (exemplary/mixed-video-banner.json). At base such an adm reached Prebid Server core as a bare URL. Core wraps only an empty adm, from nurl (git 4e296450de2f:exchange/auction.go:336-345), so the URL would be cached as the VAST XML (auction.go:267). VAST event tracking could not add its impression to it either: cwire allows VAST changes (git 789c6479e88e:static/bidder-info/cwire.yaml:6), but ModifyVastXmlString passes a VAST with no `</Impression>` through as it is (git 4e296450de2f:endpoints/events/vtrack.go:300-306, called from git 4e296450de2f:exchange/events.go:72-79). The wrapper has core's shape (VAST 3.0, empty Impression and Creatives), so event tracking now fills its Impression; core puts the URL in CDATA where the adapter escapes it, and both are valid XML.
- The add-new-bidder guide's summary of the rules says adapters must not modify bids from demand partners except from gross to net or between currencies (https://docs.prebid.org/prebid-server/developers/add-new-bidder-go.html#respect-the-rules). This change rewrites a non-empty adm the bidder sent; the ad it points to is the same URL. Nothing at base does quite that: scalibur wraps bid.ext.vastUrl only when adm is empty (git 4e296450de2f:adapters/scalibur/scalibur.go:261-263), yieldlab builds every adm itself from its own, non-OpenRTB response (git 4e296450de2f:adapters/yieldlab/yieldlab.go:381, :435-437, const.go:7), and core wraps nurl only when adm is empty. The rules file has no rule on it, so whether this counts as modifying a bid is left to the maintainer. The description says the ad server returns XML by default and that the change lets it return only the URL (github https://github.com/prebid/prebid-server/pull/5098).
- The error check the change adds can never fail. At git 789c6479e88e:adapters/cwire/cwire.go:103 `xml.EscapeText` writes to a `strings.Builder`; EscapeText returns only the errors of its writer's Write (Go source, encoding/xml/xml.go, escapeText), and strings.Builder.Write is documented to always return len(p), nil (strings/builder.go). So the return at git 789c6479e88e:adapters/cwire/cwire.go:104 cannot run and no test can reach it. The sources pull different ways: git 4e296450de2f:docs/developers/contributing.md:22 says pull requests must have 90% coverage in the changed code, and docs/developers/code-reviews.md:44 asks whether there is dead code that can be deleted, while the published guide asks adapters not to ignore errors even when one seems impossible (https://docs.prebid.org/prebid-server/developers/add-new-bidder-go.html#create-your-adapter) and enforces no coverage threshold (https://docs.prebid.org/prebid-server/developers/add-new-bidder-go.html#adapter-code-tests). The check follows the guide, so the review asks nothing of the author here.
- `http://` URLs are wrapped too (video-url.json asserts it).
