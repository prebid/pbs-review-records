## Beyond the rules

- The adapter makes its own personal-data decision (git 4e647e1b441f:adapters/optout/optout.go:175-195): it parses the TCF string and forwards user.buyeruid, user.ext.data and the device IP only when regs.gdpr is 0 or the string gives Purpose 2 consent and vendor consent for 227, and it treats an unset regs.gdpr as GDPR applying (:179-181, and gdpr 1 in the body, :274-277). Prebid Server already runs its own TCF enforcement for vendor 227 before the adapter (git 4e647e1b441f:exchange/utils.go:190-205, gdpr/impl.go:62), so the endpoint gets personal data under the stricter of the two; legitimate interest and a host's vendor exceptions do not count in the adapter's. The code calls it an additional data-minimization rule (:175-177). Not raised.
- The banner check at git 4e647e1b441f:adapters/optout/optout.go:240-243 never fails for the bidder-info as declared (banner only, on site and app), since Prebid Server drops an imp with no declared media type before the adapter, but a host can replace the capabilities in its config (git ce44c16de92a:config/bidderinfo.go:719-720). - The adapter's own body carries no floor: imp.bidfloor reaches the endpoint only inside ortb2, when an imp sets includeOrtb2 (git 4e647e1b441f:adapters/optout/optout.go:52-64, :260-265, :333-340). Not raised: whether the endpoint applies floors is the bidder's design.

## For the author

- `docs-pr-linked` pr: The description links prebid/prebid.github.io#6837, this adapter's docs PR. It merged on 2026-10-28 and made the case of `adSlot` match; at that time `dev-docs/bidders/optout.md` said `pbs: true`. On 2026-10-31, prebid.github.io#6914 set `pbs: false` on the pages of bidders that neither Prebid Server version had yet, this one included, so the page no longer shows a Prebid Server adapter. A new docs PR is needed, linked from this PR's description and merged once this adapter is: it sets `pbs: true` again, adds `pbs_app_supported: true` for the app banner this PR declares, and lists `includeOrtb2` in the Bid Params table. No open docs PR changes the page yet.
- `test-endpoint-matches-declared` optout: The tests build the adapter with `https://bid.example.test/bid` (`adapters/optout/optout_test.go:18`), whose path `/bid` is not the declared endpoint's `/prebid/display`; changing it also changes the `uri` the four fixtures expect.
- `mock-bids-like-live` optout: The live endpoint answered 204 with an empty body to the exemplary request, sent from here with its test values (publisher `152`, adSlot `home`), so no live bid could be compared with the mock. The endpoint's format has no `mtype`: the adapter types every bid banner (`adapters/optout/optout.go:500`) and drops a bid with no `currency` (`optout.go:453-459`), so the currency the live endpoint sends is what matters; the mock sets `EUR`.
- `gzip-support-known` optout: The probe could not tell whether the endpoint decompresses gzip: it answered 204 with an empty body to the exemplary request body and to a body that is not JSON, compressed or not. `static/bidder-info/optout.yaml` does not set `endpointCompression`, so Prebid Server sends it uncompressed requests.
- `usersync-gpp-macros` optout: The iframe sync URL (`static/bidder-info/optout.yaml:17`) passes `{{.GDPR}}` and `{{.GDPRConsent}}` but not `{{.GPP}}` or `{{.GPPSID}}`. It leaves out `{{.USPrivacy}}` too, which the published guide allows when US privacy does not apply to the bidder.
- `openrtb-fields-where-endpoint-reads` optout: The bidder-info declares OpenRTB 2.6. The adapter's own body carries `gdpr` and `gdpr_consent`, read from `regs.gdpr` and `user.consent` (`adapters/optout/optout.go:274-278`, `optout.go:153-172`), and no US privacy, GPP or schain field (`optout.go:52-64`); those reach the endpoint only inside the `ortb2` string, at their 2.6 locations, when an imp sets `includeOrtb2` (`optout.go:333-340`). The 2.6 declaration is what makes `regs.gdpr` reach the adapter: without it Prebid Server moves the flag to `regs.ext.gdpr`, and the adapter would send `gdpr` 1 and never forward the IP or buyer uid.
- `no-redundant-param-checks` optout: `decodeParams` rejects missing bidder params and an empty `publisher` or `adSlot` (`adapters/optout/optout.go:93-95`, `optout.go:99-101`), which `static/bidder-params/optout.json` already enforces (both required, `minLength` 1); Prebid Server validates each imp's params against it and refuses the request before the adapter runs. Removing the checks also changes two tests: the `missing bidder`, `missing publisher` and `missing adSlot` cases of `TestDecodeParams` (`optout_test.go:85`, `:88`, `:89`), and `TestMakeRequestsRejectsMixedPublisherAndInvalidImpressions`, whose imp without `adSlot` (`optout_test.go:236`) is one of the 3 errors it expects (`optout_test.go:238`).
- `no-repeat-core-work` optout: `Builder` rejects an empty endpoint (`adapters/optout/optout.go:81-83`), but Prebid Server refuses to start when an enabled bidder has no endpoint and calls `Builder` only for enabled bidders, so the branch never runs. Removing it also removes the first check of `TestBuilder` (`optout_test.go:70-72`).
- `no-needless-json-roundtrips` optout: `makeForwardableORTB2` marshals and unmarshals the whole bid request for every request the adapter sends (`adapters/optout/optout.go:202-209`, called at `optout.go:282`). When no imp sets `includeOrtb2`, the copy is read only for `device.os`, which the redaction never changes, and for `user.buyeruid` when personal data may be forwarded, when nothing is redacted (`optout.go:324-329`). A shallow copy of the request with a new `User` and a copied `Device` would do the redaction, for `ortb2` too, without the round trip and without touching the shared request.
- `use-core-helpers` optout: `MakeBids` checks the status codes by hand (`adapters/optout/optout.go:399-407`). `adapters.IsResponseStatusCodeNoContent` and `adapters.CheckResponseStatusCodeForErrors` give the same outcome (no bids for 204, a bad-input error for 400, a bad-server-response error for any other status but 200), with their own message text, so `supplemental/bad_request.json` and `supplemental/server_error.json` would expect that text instead.
- `marshal-errors-returned` optout: `normalizeCustoms` marshals a `customs` value that is an object and, when that fails, leaves the key out with no error (`adapters/optout/optout.go:120-123`). The value comes from decoded JSON, so the marshal should not fail; returning the error means giving `normalizeCustoms`, `mergeCustoms` and `mergeExtData` an error result (`optout.go:105`, `:133`, `:139`) and handling it where they are called (`optout.go:264`, `:299-312`).
- `error-construction` optout: `fmt.Errorf` builds errors with fixed text and no formatting at `adapters/optout/optout.go:82`, `optout.go:94` and `optout.go:100`, where `errors.New` is the form for fixed text. All three are in the endpoint and params checks that Prebid Server already makes, so removing those checks removes them too.
- `json-framework-coverage` optout: JSON tests reach 116 of the adapter's 213 statements; Go unit tests reach most of the rest, which JSON fixtures could reach: `imp.ext` and `imp.ext.bidder` that do not decode (`adapters/optout/optout.go:89-91`, `optout.go:96-98`), `customs` (`optout.go:107-136`), `site`, `app` and `user` `ext.data` (`optout.go:143-150`, `:299-301`, `:303-304`, `:308-311`), consent and the personal-data decision (`optout.go:159-192`), the redaction (`optout.go:214-220`), non-banner and mixed-publisher imps (`optout.go:240-257`), `gdpr` 0, request currency, device OS, `includeOrtb2` and the device headers (`optout.go:275-277`, `:288-290`, `:324-326`, `:333-339`, `:347-351`), banner `format` sizes (`optout.go:384-389`), and every bid check in `MakeBids` after the body is read (`optout.go:433-438`, `:446-483`, `:503-505`). Only `Builder`, the nil checks of the request, response and outgoing request, and the re-reading of the adapter's own body (`optout.go:81-83`, `:227-231`, `:396-398`, `:408-420`) are out of the JSON framework's reach; Prebid Server never passes those nil values either. A fixture for `includeOrtb2` has to give the whole forwarded request as the escaped string in `expectedRequest.body.ortb2`.
- `paths-covered-except-marshal` optout: No test sends `user.buyeruid` as `viewer` (`adapters/optout/optout.go:327-332`) or the device IP as `X-Forwarded-For` (`optout.go:351-358`), which happen on every request that may forward personal data (`regs.gdpr` 0, or a TCF string giving Purpose 2 and vendor 227 consent) and carries a buyer uid or an IP; a request sent from here with `gdpr` 0 did send both to the endpoint. No test passes a TCF v2 string that parses, so the Purpose 2 and vendor consent check (`optout.go:193-194`) never runs in a test; the tests pass only an empty or an unparseable string (`optout_test.go:161-162`). `app.ext` that is not an object (`optout.go:304-306`) is not reached either.
- `unmarshal-errors-covered` optout: No JSON test reaches an unmarshal error: `imp.ext` or `imp.ext.bidder` that is not an object (`adapters/optout/optout.go:89-91`, `optout.go:96-98`), a `site.ext`, `app.ext` or `user.ext` that is not an object (`optout.go:146-148`; for `user.ext` also `optout.go:168-170`, where the consent is then read as empty), a response body that is neither a list nor an object of bids (`optout.go:433-435`), or a bid's `optOutExt` that is not an object (`optout.go:471-475`). Go unit tests reach all of them but `app.ext` (`optout.go:304-306`), which no test reaches.
- `exemplary-per-media-type` optout: `static/bidder-info/optout.yaml` declares banner on app and on site, but the only exemplary test, `exemplary/banner.json`, is a site request; there is none for an app banner request.
- `mixed-valid-invalid-bids-fixture` optout: No JSON test answers with valid and invalid bids together; `MakeBids` skips an invalid bid and keeps the rest (`adapters/optout/optout.go:445-477`), which only the Go test `TestMakeBidsRejectsInvalidBidsAndPreservesValidBids` shows.
- `docs-pbs-true` optout: `dev-docs/bidders/optout.md` says `pbs: false` on master. It said `true` from 2021 until prebid.github.io#6914 set it to `false` on 2026-10-31, after #6837 merged, because no Prebid Server version had this bidder yet. A docs PR that sets it back to `true`, merged once this adapter is, is not open yet.
- `docs-list-pbs-params` optout: The docs page's Bid Params table lists `publisher`, `adSlot`, `id` and `customs`, but not `includeOrtb2`, which `static/bidder-params/optout.json` accepts.
- `docs-front-matter-current` optout: The docs page does not set `pbs_app_supported: true`, though `static/bidder-info/optout.yaml` declares app (banner).
- **Bid meta unused**: `MakeBids` decodes each bid's `meta` (`adapters/optout/optout.go:76`) and never reads it, so nothing the endpoint sends there, such as advertiser domains, reaches the bid; no bid gets `adomain`.
