## Beyond the rules

- The open PR #5065 (Aso: Enable Gzip compression), by the same author, replaces the same blank line 4 of static/bidder-info/aso.yaml with `endpointCompression: gzip`, where this PR puts `gvlVendorID: 1621` (git 1f5a6908a4df:static/bidder-info/aso.yaml:4; github https://github.com/prebid/prebid-server/pull/5065 at head 504a54874086, file blob bff9cdff0011). A three-way merge of the two versions from the base blob 6d0a86d49060 gives one conflict, at that line, so whichever PR merges second must bring in master again. Not a duplicate (record commit-pair pr-5047 v13 otherOpenPrs.prs[0] sameContent 0); not raised.
- Though no code changes, declaring the ids changes what Prebid Server does with the three bidders when a request is in GDPR scope. An alias never takes its parent's GVL id (git 1f5a6908a4df:config/bidderinfo.go:371-373). A static alias is looked up under its own name: only request aliases are mapped to a core bidder (exchange/utils.go:163, :867-869), and the id is read from that name (gdpr/impl.go:121 in the auction, :51 in cookie sync). Today a bidder with no id is refused every cookie sync in GDPR scope (gdpr/impl.go:46-58), and the full enforcement's consent and legitimate interest checks cannot pass without a vendor entry (gdpr/full_enforcement.go:69, :89). This is what the PR is for; noted for the maintainer, not raised.
- The bidgency docs page sets `tcfeu_supported: false` beside `gvl_id: 1403`, while the aso and kuantyx pages set `tcfeu_supported: true` (record docs bidgency-1f5a6908a4df v1, aso-1f5a6908a4df v1 and kuantyx-1f5a6908a4df v1 pages[0].frontMatter). Once this PR merges, Prebid Server applies TCF to bidgency under id 1403, so the page's "no" no longer fits its Prebid Server side. The value is outside the rules: `docs-front-matter-current` compares only media_types, pbs_app_supported and gvl_id. The page is not part of this PR, and it also documents a Prebid.js adapter whose TCF support no record shows. Not raised.
